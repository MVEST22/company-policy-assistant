Company Policy Assistant

Compare keyword-based retrieval, a language model with the full policy database, and a language model assisted by semantic vector search.

The rules-based method works in your browser. Actual LLM answers require the local Ollama backend on this computer; this page never fabricates model responses or benchmarks.

Comparison and preferred approach

Rules-based keyword search is fast, transparent and requires zero language-model tokens, but it often misses differently worded questions and may return an irrelevant result when common terms overlap. An LLM without vector indexing can reason over all supplied policies, though its full-database prompt has a larger token cost and can still invent unsupported information. An LLM with a vector index first retrieves semantically similar records and then answers using only those records, usually reducing generation prompt size but introducing embedding and retrieval overhead as well as a risk that a relevant policy is not retrieved.

The preferred approach is an LLM with vector-based retrieval and explicit policy citations, subject to testing its retrieval accuracy and checking responses against original source texts. All three approaches must be evaluated using the same questions, with response times and language-model token counts measured from real execution. For unsupported-answer tendency, a human reviewer should label whether each answer is fully supported, partially supported or unsupported by the policy database; the interface does not present guessed hallucination scores. For sensitive company decisions the original policy text remains authoritative.

Dataset: 98 company policies. Local comparison backend: FastAPI and Ollama. Slack integration: Socket Mode. The first vector query includes an index-build cost; compare later warmed queries separately.
